# Web 串口 / 蓝牙 I²C 工具 · 操作说明

本文档面向使用者：如何启动工具、授权并连接串口或蓝牙、在 I2C 操作台 / CH224A / MLX90614 / LIS3DH 页面完成实际操作，以及遇到问题怎么排查。实现原理见 [Web串口I2C-程序设计说明](./Web串口I2C-程序设计说明.md)，传输模块细节见 [docs/TRANSPORT_MODULES.md](./docs/TRANSPORT_MODULES.md)。

## 1. 前置条件

### 1.1 硬件

- 一块已烧录 **ESP32-Bus-Pirate LWPKT 固件**的开发板，UART 透传已启用（串口默认 **115200 8N1**）。
- **串口方式**：开发板通过 USB 连接到电脑，系统能识别为串口设备。
- **蓝牙方式**：开发板已启用 BLE NUS 串口透传（Service `6e400001-b5a3-f393-e0a9-e50e24dcca9e`），电脑支持蓝牙并已打开系统蓝牙开关。
- 目标 I²C 器件接在固件的 SDA/SCL 上，**共地**，并按器件要求加上拉电阻。
- CH224A / MLX90614 / LIS3DH 需要单独供电，接线见各自模块说明。
- LIS3DH 模块（如 Seeed Grove 3-Axis Digital Accelerometer）通过 I²C 接到固件的 SDA/SCL，地址由 SA0/SDO 引脚决定：接 GND 为 `0x18`（默认），接 VDD 为 `0x19`。

### 1.2 软件

- **Chrome 或 Edge**（Chromium 内核，版本尽量新）。Firefox / Safari 不支持 Web Serial / Web Bluetooth。
- **Deno 2.x**（用于启动开发服务器或静态托管服务）。
- 页面必须运行在**安全上下文**：`http://localhost`、`http://127.0.0.1` 或 `https://`。
  通过局域网 IP（如 `http://192.168.1.10:8787`）访问时，浏览器会禁用 Web Serial / Web Bluetooth，需要自建 HTTPS 反向代理。

> 串口是独占资源：同一时刻只能有一个程序/标签页打开它。使用前请关闭串口助手、Arduino IDE 串口监视器等可能占用端口的软件。
> 同一时刻工具只允许一个活跃连接（串口或蓝牙二选一），由传输管理器强制保证。

## 2. 启动工具

### 2.1 开发模式（推荐调试时使用）

```powershell
cd d:\Michael\myNodejs\myWebBun\i2c_web_tool
deno install
deno task dev
```

浏览器打开 `http://127.0.0.1:5174`。

### 2.2 生产模式（Hono 托管）

```powershell
cd d:\Michael\myNodejs\myWebBun\i2c_web_tool
deno task build
deno task start
```

浏览器打开 `http://127.0.0.1:8787`。`deno task preview` 等价于“先构建再启动”。

### 2.3 通过主站访问（已部署）

主站已将本工具挂到 `/i2c/`：

1. 在仓库根目录执行 `bun run build`（或 `bun run build:i2c`）完成构建。
2. 在根目录启动主站：`deno task dev` 或 `deno task start`。
3. 浏览器打开 `http://127.0.0.1:30000/i2c/`。

注意：必须保留尾斜杠。直接访问 `/i2c` 会被主站 302 到 `/i2c/`，两者最终都能用，但手动拼接资源地址时要用带斜杠的目录形式。

- 修改端口：`$env:PORT=9000; deno task start`
- 健康检查：`http://127.0.0.1:8787/api/health` 返回 `{"ok":true,...}`
- 前端路由（如 `/ch224`）直接刷新也能打开（SPA 回退）。

> 开发模式由 Vite 直接提供页面，不经过 Hono；两种模式的页面功能完全相同。

## 3. 连接设备

连接面板顶部提供 **串口 / 蓝牙** 切换。已连接时切换按钮会被禁用；即使绕过界面，
传输管理器也会在打开新传输前关闭旧传输。

### 3.1 串口：首次授权

1. 打开页面，左侧「设备连接」面板，连接方式选 **串口**。
2. 下拉框初始为空，点击 **「＋ 选择串口设备（浏览器授权）」**。
3. 浏览器弹出串口选择框，选择你的 ESP32 开发板，点“连接”。
4. 授权后端口出现在下拉框中，形如 `USB 串口 (VID:1A86 PID:7523)`。

说明：

- 浏览器只显示**尚未授权**的设备供选择；已授权的设备下次会直接出现在下拉框。
- 如果弹出的列表里没有你的设备：检查 USB 线是否支持数据传输、驱动是否安装、设备是否被其它程序占用。
- 授权记录由浏览器保存。换浏览器、换用户配置或无痕模式都需要重新授权。
- 点 **「↻ 刷新」** 可重新枚举已授权端口。

### 3.2 串口：选择波特率并连接

1. 在「波特率」下拉框选择 **115200**（与固件 UART 默认值一致）。
2. 点击 **「连接串口」**。
3. 工具会自动发送一次 **ECHO 握手**，验证链路、分帧与 CRC。
4. 成功后面板显示“串口已连接”，并列出设备、波特率、累计 CRC 错帧数。

握手失败时会自动关闭端口并提示原因，常见为：

- 固件不是 ESP32-Bus-Pirate LWPKT 固件；
- 波特率与固件不一致；
- TX/RX 未交叉、未共地；
- 设备被其它程序占用。

### 3.3 蓝牙：授权与连接

1. 连接方式切到 **蓝牙**（浏览器不支持时按钮会被禁用并显示提示）。
2. 点 **「＋ 选择蓝牙设备（浏览器授权）」**，在浏览器弹窗中选择设备。
   选择框只列出名称以 **BUS** 开头的 BLE 设备（例如 `BUS-ESP32`）；连接时再严格校验 NUS 服务。
3. 选中后点 **「连接蓝牙」**。无需设置波特率。
4. 工具会建立 GATT 连接、发现 NUS 特征、订阅通知，然后发送 ECHO 握手。
5. 成功后面板显示“蓝牙已连接”，并列出设备名与 CRC 错帧数。

说明：

- 设备名前缀由 `BLE_DEVICE_NAME_PREFIX` 定义（默认 `BUS`）；固件需把 BLE 广播名称设为该前缀开头，否则不会出现在选择框中。
- 若设备名不是 `BUS` 开头，即使已在浏览器中授权过，也不会出现在下拉列表；`listDevices()` 会过滤掉明确不匹配的设备名。
- 蓝牙写特征固定为 `6e400002-…`，通知特征为 `6e400003-…`；若固件未启用 NUS，会提示“未找到 NUS 服务或特征”。
- LWPKT 帧按 **20 字节** ATT 载荷自动分片；长帧吞吐低于串口，但协议层无差异。
- 蓝牙没有全局插拔事件；设备断电或超出范围时，GATT 断开回调会立即把页面恢复为未连接状态。

### 3.4 断开与热插拔

- 点击 **「断开设备」** 可主动释放当前连接（串口或蓝牙）。
  - 串口：取消后台读泵、释放 reader/writer 锁并 `port.close()`；
  - 蓝牙：移除通知/GATT 监听、停止通知并 `gatt.disconnect()`。
- 串口被拔出时，后台读泵会因端口失效结束并触发自动断开；浏览器的 `disconnect` 事件用于刷新端口列表。页面会清理后端状态、由 manager 补一次 `close()` 释放残留读写锁并刷新列表。
- 蓝牙断电/超出范围时，`gattserverdisconnected` 会触发自动断开、移除监听并刷新设备列表。
- 异常断开后，页面会自动等待传输层清理完成再允许重连，避免“端口仍被占用”的假失败。
- MLX90614 自动轮询在断开时自动停止并复位开关，不会在后台继续发请求。
- 重新插入/上电后，点「↻ 刷新」或重新授权/选择。
- 刷新或关闭标签页时由浏览器释放串口/GATT；工具不做后台常驻，也不会在页面关闭后继续轮询。

## 5. I²C 操作台

### 5.1 I²C 参数设置

连接成功后，左栏「I²C 参数」卡片会显示当前 SDA、SCL 与总线频率。页面会根据固件
上报的芯片能力，自动切换两种界面：

| 界面 | 适用芯片 | 操作 |
| --- | --- | --- |
| 自由引脚（固件上报表） | ESP32 / ESP32-S3 / C3 / C6（CAPS v2） | 从下拉框选择固件声明的可用 SDA/SCL |
| 自由引脚（旧固件） | 无 CAPS 或 CAPS v1 的 ESP32 | 输入 SDA/SCL 的 GPIO 号与频率 |
| 固定复用 | STM32 | 选择 I2C1/I2C2… 与固件提供的引脚方案 |
| 兼容模式 | 不支持 CAPS 的旧固件 | 按自由引脚处理 |

自由引脚（固件上报）：

1. 页面连接后读取 CAPS，SDA/SCL 变为下拉框，只列出固件声明可用的 GPIO。
   选项可能带「默认」「启动引脚」「无内部上拉」标记。
2. 展开「固件上报：…」可查看被排除的引脚及原因（Flash/PSRAM、USB、UART0、仅输入等）。
3. 选择引脚与频率，点「应用引脚与频率」。固件会重建总线，约 1 秒，期间不要断电。
4. 成功后面板刷新；旧扫描结果会清空，请重新扫描。

自由引脚（旧固件）：

1. 在 SDA/SCL 输入框填写 GPIO 号（0–63）。**不能使用 43/44**，它们是 ESP32 的
   UART0 控制台引脚。
2. 填写频率（kHz），或点 `100 kHz` / `400 kHz` / `1 MHz` 预设。
3. 点「应用引脚与频率」；成功后面板刷新、旧扫描结果清空。

固定复用（STM32）：

1. 在「I²C 实例」下拉框选择 I2C1、I2C2…。
2. 在「引脚方案」下拉框选择默认/备用/remap 方案，下方会显示 SCL、SDA 与 AF 编号。
3. 点「切换实例与引脚」。
4. 若固件声明支持交换 SDA/SCL，才会显示「交换 SDA/SCL」；「总线恢复」用于从机
   拉死总线时发送 9 个时钟。

注意：

- STM32 的引脚由复用功能固定，**不能任意输入 GPIO**；只能选固件上报的方案。
- ESP32 的可用引脚由 CAPS v2 上报；列表之外的引脚会被前后端拒绝。旧固件没有引脚表时
  显示数字输入。
- 旧固件没有 CAPS 时显示“兼容模式 · 自由引脚”，此时按 ESP32 方式设置。
- 修改参数会短暂释放总线，正在进行的读写会失败，等操作完成后再改。
- 协议细节、STM32 引脚表与 ESP32 固件协议分别见 `docs/I2C_BUS_CONFIG.md`、
  `docs/STM32-I2C-PINMAP.md`、`docs/ESP32_FIRMWARE_PROTOCOL.md`。

### 5.2 总线扫描

1. 在“总线扫描”卡片填入起始/结束地址（默认 `0x08` – `0x77`）。
2. 点击“扫描”。
3. 页面列出应答的 7 位地址，例如 `0x50`、`0x5A`。

说明：

- 固件会扫描整段总线，工具再按你填写的范围过滤显示。
- 地址范围必须是 `0x08 ≤ 起始 ≤ 结束 ≤ 0x77`。
- 扫描不到任何设备时：检查器件供电、SDA/SCL 接线、上拉电阻、地址是否正确。

### 5.3 寄存器读写

1. 输入器件地址（7 位，如 `0x50`）和寄存器地址（如 `0x00`）。
2. 点“读取”，结果显示在历史与写值输入框中。
3. 修改“写入值”后点“写入”，成功会记录一条写入历史。

> 写入是**立即生效**的。对配置寄存器、控制寄存器操作前请确认地址与值，避免误改器件状态。

### 5.4 原始传输

“原始传输”用于发送任意 I²C 命令流，语义与 CH341 的 `transfer` 一致：

- 发送数据的**首字节是 8 位写地址**（7 位地址左移一位）。
- 其后的字节是寄存器/数据前缀。
- “读取长度”为 0 表示只写；大于 0 表示写完后读回指定字节数。

示例：

| 发送数据 | 读取长度 | 实际行为 |
| --- | --- | --- |
| `A0 00` | `2` | 向 0x50 写寄存器指针 0x00，然后读 2 字节（READ_BLOCK） |
| `A0` | `8` | 仅地址相位，读 8 字节（READ_RAW） |
| `A0 00 20` | `16` | 16 位寄存器地址 0x0020，读 16 字节（READ_MEM16） |
| `A0 01 FF` | `0` | 向 0x50 写寄存器 0x01 = 0xFF（WRITE_RAW） |

前缀长度决定读命令：

- 0 字节前缀 → READ_RAW（每次 ≤255 字节）
- 1 字节前缀 → READ_BLOCK（寄存器自增，每次 ≤255 字节）
- ≥2 字节前缀 → READ_MEM16（取前两字节作为 16 位地址，每次 ≤1000 字节）

读取长度上限 4096 字节，超过会直接拒绝。

### 5.5 EEPROM（24Cxx）

1. 切换到“EEPROM”标签页。
2. 选择型号（24C01 – 24C4096）。
3. 填写偏移（支持 `0x` 前缀）与读取长度，点“读取”。
4. 写入时填写十六进制数据（如 `AA BB CC DD`），点“写入”。

流程与限制：

- 读写前会先发 `EEPROM_OPEN`，由固件确认器件应答并返回容量；无应答会报“无应答”。
- 器件地址固定为 `0x50`（A2/A1/A0 = 0）。
- 单次传输最大 4096 字节，内部按 ≤1000 字节分片。
- 型号映射沿用桌面版假设 `model = 型号编号 + 1`。若固件报容量与所选型号明显不符，请先核对型号选择。

## 6. CH224A PD 取电

### 6.1 发现与能力读取

1. 打开 CH224A 页面。
2. 点“扫描”查找 `0x22` / `0x23` 地址。
3. 选择地址后点“读取能力”（或页面自动读取），查看：
   - 状态寄存器 `0x09` 的协议位；
   - 电流能力 `0x50`；
   - `0x60–0x8F` 的 Source Capabilities（PDO/APDO 列表）。

> 若状态寄存器读回 `0xFF`，页面会提示“模块未上电或 I²C 无应答”，并且**不会**允许写入取电配置。先检查 VCC/GND 与上电状态。

### 6.2 取电模式

| 模式 | 适用条件 | 写入内容 |
| --- | --- | --- |
| 固定 PDO | PD 激活，电源广播了该固定档 | 模式寄存器 `0x0A` = 档位编码 |
| PPS | 存在覆盖目标电压的 PPS APDO | `0x53` = 电压/100mV，`0x0A` = 6 |
| AVS | AVS 能力位置位，存在覆盖目标电压的 AVS APDO | `0x51/0x52` = 电压/10mV，`0x0A` = 7 |
| QC/其它 | PD/EPR 未激活，检测到 QC2/QC3/BC | `0x0A` = 固定档编码（按协议白名单） |

安全规则：

- 目标档位未被电源广播时，工具**拒绝写入**，输出保持现状。
- 请求 >20 V 固定档时要求 EPR 已激活。
- 写入后延时 120 ms 读 `0x09`：读回 `0xFF`（疑似掉电）或 `0`（握手失败）都会报错。
- `0x0A/0x51/0x52/0x53` 是只写寄存器，无法回读确认。
- 页面提示的“已写入”只代表 I²C 配置成功，**不代表 VBUS 已达到目标电压**；请用万用表确认后再接负载。

### 6.3 手动寄存器操作

页面提供 CH224A 寄存器列表与单字节读写：

- 读取会显示语义解读（协议位、电压模式等）。
- 写入只写寄存器时会提示“无法读回确认，请通过 0x09 状态位判断握手结果”。
- 可读回寄存器会自动比对写入值与回读值。

## 7. MLX90614 测温

### 7.1 发现与温度读取

1. 打开 MLX90614 页面，点“扫描”检查 `0x5A` 是否应答。
2. 选择温度寄存器（如 `0x07` 对象温度、`0x06` 环境温度）。
3. 点“读取温度”，页面显示：
   - 原始 16 位值；
   - 摄氏度 / 华氏度；
   - PEC 校验是否通过；
   - 是否无响应（`0xFFFF`）。

自动轮询间隔可选 0.3 / 0.5 / 0.8 / 1 秒，1 秒以上按 1 秒步进（最大 30 秒）；开启后周期性读取并绘制曲线，停止轮询后不再占用串口。

### 7.2 寄存器读写

- 读取 16 位寄存器会同时校验 SMBus PEC；PEC 失败会提示可能受总线干扰。
- 写入按地址分类：
  - **RAM `0x00–0x1F`**：只读，工具直接拒绝。
  - **EEPROM `0x20–0x3F`**：执行“擦除 → 写值 → 回读校验”，每步之间延时 10 ms。
  - **命令 `0x60–0x7F`**：只发送命令字节，无数据/PEC。

### 7.3 发射率

- 发射率范围为 **0.1–1.0**，存储在 EEPROM `0x24`。
- 写入后会自动回读比对；不一致会提示重试或检查供电。
- 发射率、地址、配置等 EEPROM 参数通常需要**重新上电**后才完全生效。

> EEPROM 写入次数有限，请避免频繁修改。写入过程中不要断电。

## 8. LIS3DH 三轴加速度

### 8.1 发现与首次读数

1. 打开「LIS3DH 加速度计」页，点「扫描 0x18 / 0x19」。
2. 工具对两个地址读 `WHO_AM_I`（`0x0F`，固定 `0x33`）：
   - `0x18`：SA0/SDO 接 GND（模块默认）；
   - `0x19`：SA0/SDO 接 VDD。
3. 识别成功后自动选中该地址，并把六个配置寄存器（`CTRL_REG1/3/4/5`、`TEMP_CFG`、`FIFO_CTRL`）的当前值填进「02 工作模式配置」。
4. 默认处于「单次轮询」读取模式，自动读取开启后每 100 ms 读一次三轴（间隔可在 20–1000 ms 间调整）。

一次读数会同时给出四个层次的量：

| 显示 | 含义 |
| --- | --- |
| X / Y / Z 卡 | 换算后的加速度，单位 g，带符号与进度条 |
| `原始 —` | 芯片输出的有符号计数（按输出模式 8/10/12 位，统一左对齐到 16 位） |
| `\|g\|` | 三轴合成模长；静止时应接近 `1.000 g` |
| Pitch / Roll | 由重力方向算出的俯仰/横滚角，单位 ° |
| 温度 | `OUT_ADC3` 通道，约 1 °C/LSB、+25 °C 偏移，仅供相对参考 |

上方「立体姿态」用等轴测投影把三轴映射到固定坐标架：**+X 指向屏幕右下、+Y 指向屏幕左下、+Z 竖直向上**，
画面上有三轴箭头（带刻度与标签）、地面网格、随重力倾斜的器件板，以及一条从原点指向当前加速度的发光矢量
（末端有落地虚线与地面投影）。转动模块时矢量与器件板同时跟着动；静止放平时矢量应竖直指向重力方向、长度约 1 g。
3D 视图在上、三轴数值卡在下，上下排列，窄屏也不用左右挤压。

> 100 ms 是**读取周期**，不是芯片的输出速率。要让每次读到的都是新数据，ODR 最好 ≥ 2× 读取率
> （默认 100 Hz）。把 ODR 调到 10 Hz 后，两次读数之间会拿到同一份数据；参数行会直接给出警告。

### 8.2 量程与工作模式

「02 工作模式配置」对应六个寄存器，写入后立即回读校验：

| 控件 | 寄存器 | 说明 |
| --- | --- | --- |
| 量程 FS | `CTRL_REG4[5:4]` | ±2 / ±4 / ±8 / ±16 g；量程越小分辨率越高 |
| 输出速率 ODR | `CTRL_REG1[7:4]` | 掉电、1 Hz – 1.344 kHz（低功耗下最高 5.376 kHz）；100 Hz 为推荐值 |
| 输出模式 | `CTRL_REG1[3]` + `CTRL_REG4[3]` | 低功耗 · 8 位 / 正常 · 10 位 / 高分辨率 · 12 位 三档互斥 |
| 块更新 BDU | `CTRL_REG4[7]` | 防止读到高低字节来自不同采样（读数不撕裂） |
| 中断路由 | `CTRL_REG3` | 不输出 / 数据就绪 ZYXDA→INT1（`0x10`）/ FIFO 水印 WTM→INT1（`0x04`） |
| FIFO | `CTRL_REG5[6]` + `FIFO_CTRL` | 启用、模式（Bypass / FIFO / Stream / Stream-to-FIFO）、水位阈值 1–31、复位 |
| 温度通道 | `TEMP_CFG[6]` | 启用后 `OUT_ADC3` 输出温度，ADC3 被占用 |
| 轴使能 | `CTRL_REG1[2:0]` | 关闭某轴可省电，该轴读数不再更新 |

点「下发并回读」后，页面显示写入的六个字节、回读值与 `matches` 是否一致。
量程改变会**立即**改变换算系数，切换后请等下一次读数再判断姿态。
输出模式三档只是分辨率与噪声不同：数据统一左对齐到 16 位，**换算系数不变**。
`LPen=1` 与 `HR=1` 同时置位是手册禁止组合——页面用三按钮互斥，从结构上排除了这种情况。

### 8.3 四种采样读取模式

「01 读取模式」提供四种数据通道，切换时页面自动准备芯片：

| 模式 | 数据路径 | 适合场景 |
| --- | --- | --- |
| 单次轮询 | 每条间隔发一次 `0xA8` 连读命令（6 字节） | 低频观察（≤50 Hz）；最简单 |
| FIFO 批量 | 芯片先攒样本，周期到了一次读走多组 | 中高频、不想频繁发命令；不丢样本 |
| 中断推送 | 固件读好数据主动上报，页面零轮询 | 高频（≥200 Hz）；需固件支持 + INT1 接线 |
| 周期上报 | 固件按设定周期自读 `0xA8` 并推 `REPORT_DATA` | 长期无人值守、可自定义周期（1–60000 ms）；需固件支持 `REPORT_*` |

**单次轮询**：在模式卡片的参数行选择读取间隔（20–1000 ms）。读取率 ≈ 1000 ÷ 间隔；
页面会按当前 ODR 提示 `ODR ≥ 2× 读取率`，低于时出现警告——此时读数会重复。

**FIFO 批量**：切到该模式会自动启用 FIFO（Stream 模式、阈值 16 或沿用已设值），
并按「批量读取周期」（50–1000 ms）周期读取。每个周期一次事务读走 FIFO 中全部样本（最多 32 组）；
读取后页面显示本批组数与余量。读取间隔应小于「阈值 ÷ ODR」，否则提示「没有可读样本」
（读得比攒得快）——参数行会按当前 ODR 直接给出建议间隔。退出模式时自动写回 Bypass。

**中断推送**（需要硬件配合）：

1. 把 LIS3DH 的 **INT1 引脚接到主控的一个空闲 GPIO**（避开 I²C 引脚与保留引脚）；
   页面的「INT1 接入引脚」会按固件上报的平台给出定义——ESP32 是自由引脚下拉（默认 `GPIO4`，
   仅列 CAPS 可用引脚，含仅输入引脚），STM32 是端口下拉（`PA4`、`PB6` 这类，编码 `port*16+pin`），
   旧固件才会退回数值输入；
2. 固件需实现 STREAM 命令（`0x0230`/`0x0231`/`0x0232`），字节布局、引脚编码与接线要求见
   [docs/LIS3DH_STREAM_PROTOCOL.md](./docs/LIS3DH_STREAM_PROTOCOL.md)；
3. 模式参数行选触发方式（数据就绪 / 固件定时）；中断触发时选引脚、定时推送时填周期；
4. 点「启动推送」：页面先自动把 INT1 路由写为 ZYXDA 并关掉 FIFO，再下发 `STREAM_START`；
5. 页头显示「推送中 · 实测 N Hz」，状态行给出「推送帧 / 丢帧 / 本批组数」；
6. 切回其它模式或断开连接时，页面自动退订并下发 `STREAM_STOP`。

> 中断推送时页面**不做任何轮询**，只处理固件推上来的数据；渲染按 60 fps 节流，
> 数据再快也不会拖慢页面。若固件未实现 STREAM 命令，启动时会给出明确提示
> （旧固件可继续使用单次轮询 / FIFO 批量）。
>
> 引脚行下方会显示当前定义，例如「INT1 → GPIO4（编码 0x04）」或「INT1 → PB6（编码 0x16）」；
> 换芯片、改 I²C 引脚后候选会自动剔除保留引脚与已占用的 SDA/SCL。

**周期上报**（需要固件实现 `REPORT_*` `0x0240–0x0245`）：

1. 点「周期上报」卡片，参数行出现「上报槽位 / 上报周期 ms / 帧数上限」：
   - 槽位 0–15，同一槽位只能跑一个任务，避免和「周期自动上报」页抢占；
   - 周期 1–60000 ms，也可点「常用周期」快捷档位（20/50/100/200/500/1000 ms）；
   - 帧数上限 `0` 表示一直推到停止；
2. 点「下发并启动」：页面依次下发 `REPORT_CONFIG`（地址取上方器件地址、寄存器固定 `0xA8`、长度固定 6）
   与 `REPORT_START`，提示会回显固件**实际生效**的周期（固件可能按调度 tick 钳制）；
3. 运行中修改周期后，按钮变为「应用新周期并重启」——先停再配再启，避免固件拒绝运行中改配；
4. 数据卡与 3D 视图跟随上报帧刷新，状态行给出「上报帧 / 丢帧 / 设备间隔」；
   「设备间隔」用的是帧内 `atMs`（设备采样时刻）差值，能直接看出固件是不是按周期在跑；
5. 点「停止上报」结束本槽位；切到其它读取模式或断开连接时也会自动停掉本页槽位。

> 周期上报与中断推送互斥：要切回中断推送，页面会先等 `REPORT_STOP` 完成再启动 `STREAM_START`。
> 旧固件（无 `REPORT_*`）会提示「当前固件不支持周期自动上报」并禁用按钮。
> 若想多个器件同时上报，请到「周期自动上报」页配置多槽位；本页固定只用一个槽位读三轴。

### 8.4 寄存器表与手动读写

页面「03 手动寄存器」提供：

- **37 条寄存器地址表**：地址、名称、读写属性、功能说明，最多显示 6 行，其余在表内滚动；
- **单字节读**：显示十六进制、二进制、原始值，并按位域展开（如 `CTRL_REG4` 的 BDU/BLE/FS/HR/ST/SIM）；
- **单字节写**：写入后自动回读比对；只读寄存器会被器件忽略，此时 `matches` 为 false 属正常现象。

`0x0F WHO_AM_I` 是最可靠的“器件在不在”检查点：读回 `0x33` 才算 LIS3DH。
`0x27 STATUS_REG2` 的 bit3 是数据就绪（ZYXDA），bit7 是溢出（ZYXOR）。

### 8.5 性能参数与用法要点

页面「04 性能参数」列出供电、量程、分辨率、灵敏度、ODR、I²C 速率、地址、噪声、工作电流、
温度传感器、中断能力与 FIFO。几条容易踩的：

- **12 位左对齐**：原始值低 4 位恒为 0，换算用库里的除数（`16000/7282/3968/1280`），
  不要直接套手册的 1/2/4/12 mg/digit，否则会差 16 倍。
- **温度精度有限**：1 °C/LSB、±数度误差，只适合看相对变化；启用后 ADC3 不能再作他用。
- **中断与 FIFO 已有基础配置**：INT1 路由（数据就绪 / FIFO 水印）、FIFO 模式与阈值
  均可在「02 工作模式配置」直接设置；更复杂的阈值中断（自由落体、单击检测）仍需手动写
  `INT1_CFG` / `INT1_THS` / `INT1_DURATION`。

### 8.6 推荐操作顺序

1. 连接设备 → 扫描 → 确认 `WHO_AM_I = 0x33`；
2. 用默认「单次轮询」读一次，确认静止时 `|g|` ≈ `1.000`；
3. 需要更大动态范围（跌落、冲击）时先改 FS，再观察是否削顶；
4. 按目标速率选读取模式：
   - ≤50 Hz 用单次轮询（间隔 20–50 ms）；
   - 中高频先试 FIFO 批量（按页面建议的批量周期）；
   - ≥200 Hz 或要零轮询，用中断推送（接 INT1 + 固件支持）；
5. 任何模式下都保持 ODR ≥ 2× 读取率（页面有动态提示）；
6. 需要长时间无人值守、由固件自己按节奏采集时，选「周期上报」并设置周期；
   它把任务交给固件，页面不再发读命令，切页/刷新前记得先「停止上报」或让断开自动停；
7. 需要温度时勾选温度通道并下发（仅轮询模式附带温度读数）；
8. 调参后读数异常时，先读 `CTRL_REG1/3/4/5` 与 `FIFO_CTRL` 确认位域，再决定是否重新下发。

## 9. 示例流程

### 9.1 读取 24C02 的前 16 字节

1. 连接设备（串口或蓝牙，ECHO 握手通过）。
2. I²C 操作台点“扫描”，确认 `0x50` 应答。
3. 切到 EEPROM 标签页，型号选 `24C02 · 256 B`，偏移 `0x00`，长度 `16`。
4. 点“读取”，结果显示 16 字节 hex 与 ASCII。

### 9.2 用 CH224A 请求 20 V

1. CH224A 页面扫描到 `0x22`，读取能力，确认电源广播了 20 V 固定 PDO。
2. 模式选“固定”，电压选 20 V，提交请求。
3. 查看状态位与提示；用万用表确认 VBUS 达到 20 V 后再接负载。

### 9.3 读取 MLX90614 对象温度

1. MLX90614 页面扫描到 `0x5A`。
2. 选择对象温度寄存器 `0x07`，点“读取温度”。
3. 确认 PEC 通过；若显示“无响应”，检查模块供电与上拉。

### 9.4 用 LIS3DH 检查模块朝向

1. LIS3DH 页面扫描到 `0x18`，确认 `WHO_AM_I = 0x33`。
2. 保持模块静止，等 `|g|` 稳定在 `1.000` 附近。
3. 平放（丝印朝上）：Z 轴 ≈ `+1 g`，Pitch / Roll ≈ 0°。
4. 翻转 180°：Z 轴 ≈ `-1 g`；侧立时对应轴接近 ±1 g，另两轴接近 0。
5. 若三轴始终是同一组数，先看 02 区 ODR 是否 ≥ 2× 读取率，再确认没有绕过 `0xA8` 块读。

### 9.5 用周期自动上报同时采集两个器件

前提：固件已实现 `REPORT_*`（`0x0240–0x0245`）。旧固件在打开本页时会提示“不支持”并禁用按钮。

1. 先连接设备（在 I²C 操作台完成），再点导航「周期自动上报」。
2. 01 区填第一个槽位：任务编号 `0`、地址 `0x18`、起始寄存器 `0xA8`（LIS3DH 自增块读）、
   长度 `6`、周期 `100` ms、帧数上限 `0`（不限），点「下发配置」。
3. 改任务编号为 `1`，填 `0x5A` / `0x07` / `3` / `1000` ms，再「下发配置」。
4. 02 区点「刷新任务表」，确认两个槽位状态为「已配置」。
5. 点「启动全部」，顶部状态行显示运行中数量；03 区会按 taskId 出现两张数据卡。
6. 观察每卡的「帧数 / 丢帧 / 设备间隔」：设备间隔应接近配置周期（如 100 ms）；
   丢帧持续增长说明链路带宽不足或主机阻塞。
7. 结束时点「停止全部」，提示会给出各任务累计帧数；要改配置先停止对应槽位，否则固件回 `ERR_ARG`。

注意：周期自动上报与 LIS3DH 的「中断推送」互斥；要切回中断推送，先在本页「停止全部」。
切到其它页面不会停止上报（固件仍在推帧），需要停就回本页或断开连接。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 页面提示“当前浏览器不支持 Web Serial API” | 使用了 Firefox/Safari，或非安全上下文 | 换 Chrome/Edge；用 localhost / 127.0.0.1 或 https |
| 页面提示“当前浏览器不支持 Web Bluetooth API” | 浏览器无 Web Bluetooth，或系统蓝牙未开启 | 换 Chrome/Edge；打开系统蓝牙并授予浏览器权限 |
| 串口下拉框为空 | 从未授权、线材只供电、驱动缺失 | 点「＋ 选择串口」授权；换数据线；装驱动 |
| 蓝牙列表为空 | 设备未广播、系统未配对、距离过远 | 确认固件已启用 BLE；在系统设置中配对；靠近设备 |
| 蓝牙提示“未找到 NUS 服务或特征” | 固件未启用 NUS 透传，UUID 不符 | 核对 `6e400001/2/3` 与固件定义 |
| 蓝牙提示“设备未授权” | 刷新后设备缓存丢失 | 重新点「＋ 选择蓝牙设备」授权 |
| 选择框里没有设备 | 设备被占用或未枚举 | 关闭串口助手/Arduino IDE；重新插拔；看设备管理器 |
| 连接失败“无法打开串口” | 端口被占用、驱动异常 | 关闭占用程序；重插；必要时重启浏览器 |
| “串口已连接但握手失败” | 固件不对、波特率不符、TX/RX 未交叉、未共地 | 核对固件与接线，确认 115200 8N1 |
| “蓝牙已连接但握手失败” | 固件未转发 NUS 数据、分片/MTU 异常 | 确认固件 NUS 透传；缩短距离；增加 `writeDelayMs` |
| 操作超时（2000 ms 无应答） | 固件未响应、链路干扰、命令不被支持 | 看提示中的“最后发送帧”，核对固件日志；降低波特率 |
| CRC 错帧数持续增长 | 线太长、干扰、波特率偏差 | 缩短杜邦线、共地、降低波特率；蓝牙远离 2.4 GHz 干扰源 |
| “器件无应答” | 地址错误、未上电、缺上拉、SDA/SCL 接反 | 核对地址与接线，测量供电 |
| CH224 读回全 `0xFF` | 模块未上电或 I²C 无应答 | 检查 VCC/GND，重新上电后再读 |
| MLX 读数全 `0xFF` | 未上电、地址不对、PEC 受扰 | 检查供电与上拉；降低 I²C 速度后重试 |
| EEPROM 容量不符 | 型号选错，或 `model = type + 1` 假设不匹配 | 核对芯片丝印；必要时校准固件型号编号 |
| 插入设备后列表没变 | 新设备尚未授权 | 点「＋ 选择设备」重新授权 |
| 刷新页面后要重连 | 页面刷新会释放串口/蓝牙连接 | 重新选择设备并连接（串口授权记录保留） |
| 另一个标签页打不开串口 | 串口被第一个标签页占用 | 关闭占用标签页或先断开 |
| 扫描不到 LIS3DH | 模块未上电、SA0 接错、未共地 | 核对地址 `0x18`/`0x19`；读 `WHO_AM_I` 应得 `0x33` |
| LIS3DH 三轴恒为同一组值 | ODR 低于读取率，或块读未置子地址 MSB | 按页面提示把 ODR 调到 ≥2× 读取率；用页面默认块读路径（`0xA8`） |
| LIS3DH 读数全为 0 | `CTRL_REG1` 的 ODR=0（掉电）或轴未使能 | 在 02 区重新下发配置并查看回读值 |
| LIS3DH 温度恒为 0 | `TEMP_CFG.TEMP_EN` 未置位 | 勾选「温度通道」后下发；注意 ADC3 被占用 |
| FIFO 模式提示「没有可读样本」 | 批量读取周期太小（读得比攒得快） | 按参数行给出的建议加大批量读取周期，或提高 ODR |
| 启动推送提示「固件需实现 STREAM_START」 | 固件未实现 STREAM 命令（旧固件） | 升级固件（见 `docs/LIS3DH_STREAM_PROTOCOL.md`），或继续用轮询 / FIFO 模式 |
| 推送已启动但无数据进页 | INT1 未接到固件实际监听的 GPIO、上拉/共地问题 | 检查跳线；对照启动提示中的“引脚”描述；试着先回轮询模式验证 I²C 通路 |
| 推送速率远低于 ODR | I²C 失败被跳过、或链路带宽不足（蓝牙/115200 串口） | 看“丢帧”与“推送帧”差值；高速率改用 FIFO 成批推送并考虑提高波特率 |
| 自动上报页提示“固件不支持周期自动上报” | 固件未实现 `REPORT_*`（旧固件） | 升级固件（见 `docs/AUTO_REPORT_PROTOCOL.md`）；按钮会禁用到重连为止 |
| 已「启动全部」但数据卡没有帧 | 槽位未下发配置、器件无应答、或周期很长 | 先「刷新任务表」看状态列；确认器件已上电且地址正确 |
| 运行中的槽位「下发配置」报 ERR_ARG | 固件要求先停止再改配置 | 先点该行的「停止」或「停止全部」，再下发 |
| 启动上报提示“中断推送运行中” | STREAM 与 REPORT 互斥 | 先去 LIS3DH 页停止「中断推送」 |

## 11. 使用限制与注意事项

- 仅支持 Chromium 内核浏览器；移动端浏览器通常不支持 Web Serial / Web Bluetooth。
- 同一时刻只能有一个活跃连接（串口或蓝牙）；切换连接方式会先关闭旧连接。
- 蓝牙 NUS 默认按 20 字节分片，长帧吞吐低于串口；蓝牙没有全局插拔事件，依靠 GATT 断开回调更新状态。
- 串口固件不支持 SPI，本工具不提供 SPI 页面。
- 浏览器无法清理操作系统串口缓冲；极少数时序下可能遇到一次“迟到应答”导致的超时，重试即可。
- 页面刷新、关闭标签页、浏览器崩溃都会释放串口/蓝牙连接；操作记录只在内存中，不会持久化。
- 多标签页同时使用同一串口会失败，这是浏览器的独占行为。
- EEPROM 写入有寿命限制；CH224 取电配置写入前请确认目标档位与负载安全。
- I²C 状态位不等于实际电压/温度测量，关键场景请用万用表或外部仪器复核。
- LIS3DH 的 100 ms 是页面轮询周期：蓝牙分片下单帧往返更慢，实际周期可能略大于设定值；
  静止时 `|g|` 约为 1 g 可作为接线与换算正确性的快速自检。
- LIS3DH「中断推送」需要硬件与固件配合：INT1 → 主控空闲 GPIO 的跳线，以及固件实现
  STREAM 命令；旧固件继续可用轮询 / FIFO 模式。
- LIS3DH 页的「周期上报」固定占用一个槽位、读 `0xA8` 六字节，周期 1–60000 ms；
  与中断推送互斥，切到其它模式或离开页面时页面会自动停掉该槽位。
- 周期自动上报需要固件实现 `REPORT_*`（`0x0240–0x0245`）；页面与样式已上线，但当前旧固件只能看到“不支持”提示。
- 自动上报的运行状态保存在固件里：切到其它页不会停推，刷新页面/断开连接才会停；重新打开本页会自动拉取任务表，但数据卡与帧数从零重新累计。
- `atMs` 是设备时间戳（u32，约 49.7 天回绕），不要用它反推主机时间；设备重启后设备间隔会重新起算。
